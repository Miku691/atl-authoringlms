Academic Session Lifecycle & Flow

This flow explains how academic sessions are created, managed, and used to drive the institutional calendar.

Step-by-Step Flow

1. Definition & Creation

Admin uses the Session Setup Wizard in the Web UI to define the session name (e.g., "2026-2027") and date range. A POST /sessions request is sent to the Academic Service.

2. Structural Cloning

If a source session is selected, the UI calls POST /sessions/{id}/clone-structure. The AcademicSessionCloneService recursively copies Offerings, Subjects, Instructors, and Class Mappings.

3. State Management

The session moves from DRAFT to ENROLLMENT_OPEN. This transition allows the Student Service to begin enrolling students into the offerings defined within this session.

4. Operational Activation

When the academic term begins, the session is marked as ACTIVE. This enables attendance tracking, exam scheduling, and daily operations.

Technical Implementation Details

Component Responsibility
AcademicSession Entity Stores metadata, status, and isLocked flag.
AcademicSessionCloneService Handles deep-copy logic for offerings and mappings across sessions.
SessionManagementPage.tsx React-based wizard for guided session setup.
AcademicReadinessService Validates that a session exists and has offerings before allowing operations.

How to Use This Feature

Scenario: Starting a New Year

  1. Go to Academics → Academic Sessions.
  2. Click + New Session Setup.
  3. In Step 2, select the Current Session as the source to clone your entire class/subject structure.
  4. Verify the cloned offerings in the "Offerings" page.
  5. Change status to Open Enrollment once you are ready to accept students.
