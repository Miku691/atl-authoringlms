Mapping & Implementation Notes

  • Use offerings as canonical run/cohort. All enrollments, timetable, attendance and assignments reference offering_id.
  • Set offerings.type = SCHOOL_CLASS | COLLEGE_PROGRAM | COACHING_BATCH to drive behavior. Avoid spreading type checks; encapsulate logic in domain services.
  • Store flexible configs in tenant_settings.settings JSON. Example defaults: { "attendance_mode":"PER_DAY", "timetable_mode":"WEEKLY" }.
  • Index high-churn tables: attendance_records(attendance_master_id), offering_subjects(offering_id), student_enrollments(offering_id) (student_enrollments is in student-service but queries will reference offering).
  • Keep heavy, frequently-read views (e.g., current class roster) as materialized views or caches to minimize joins across services.
  • Exam tables are Phase-2. Start with assignments & attendance in Phase-1 to validate academic flows.
